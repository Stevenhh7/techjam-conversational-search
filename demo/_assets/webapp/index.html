How this demo maps to Track 4 · Shopping Copilot

The challenge requires an intelligent conversational shopping agent over a frozen Amazon catalog with four pillars. This page exercises the real pipeline in the solution/ package — no mock data.

Pillar coverage

PillarImplemented in this demo
I. Intent Routing & Hybrid PipelineDual-track routing (Buying → precision filter track / Browsing → discovery track); multi-route retrieval BM25 + category + metadata (+ dense when the artifact is present) → LLM semantic re-ranking. Watch the “Model prediction” panel in the Live Inference tab.
II. Multi-Turn Scenario EvolutionDynamic state machine: slot accumulation, intent override (slot erase/rewrite), proactive clarification on over-generality with retrieval cutoff. Send “Actually, ignore my earlier preference…” mid-session to see an override.
III. Self-Evolution (Context Programming)Short-term session state + long-term user profile drive per-turn queries and ranking; runtime re-orchestration (provisional vs full pipeline, route weights, safe fallback).
IV. Evaluation MatrixHit Rate@10, MRR, MTTC, Efficiency and TechnicalScore are produced by the unmodified official evaluator. The dashboard displays tracked dev150 aggregate evidence instead of reading labels during the live demo.

LLM on / off / failure — how it is handled

  • LLM OFF (default deterministic): the local-LLM ranker is replaced by a DisabledSemanticRanker; retrieval fusion + heuristic scoring order the Top-10. Fast and fully offline.
  • LLM ON: each turn asks the local Ollama model (e.g. qwen3.5:9b) to re-rank only the top candidates with a JSON-schema-constrained permutation.
  • LLM failure (Ollama down / timeout / malformed JSON): the ranker is fail-open — it falls back to the deterministic order, opens a circuit breaker so later turns stay fast, and reports applied=false + reason in the prediction panel (try it: turn the LLM on while Ollama is not running).
